# Regex builder: RegexBuddy parity matrix

The regular expression builder is held to the functional baseline of the official [RegexBuddy manual](https://www.regexbuddy.com/manual.html) (family list reviewed on 2026-11-04 against the maintainers' parity checklist). This is an independent implementation: no RegexBuddy code, text or assets are used.

**Status is stated per topic, never as a family tick.** The parity requirement stays **open**: 73 of 83 topics are implemented, 2 are partial and 8 are unavailable. All eight unavailable topics cannot exist on the .NET regular expression engine (debugger trace and debugging from the cursor, step counts, possessive quantifiers, recursion, class intersection, branch reset, replacement conditionals); nothing that .NET allows is left unbuilt, but two topics are only partly covered (the version remarks of the flavor comparison, and scripting and automation beyond the command line).

- **implemented**: built, covered by a focused check in `tests/UiState/Program.cs`, and applicable to the .NET engine.
- **partial**: some of the topic works; the reason and the missing part are stated.
- **unavailable**: not built, or impossible on this engine; the exact reason is stated.

**Not verified:** none of the interface below has been exercised in the running application or captured as a HuiShot. Every "implemented" row is backed by logic checks on the framework-free engine classes only (`tests/UiState/Program.cs`, `tests/UiState/RegexRemainingChecks.cs`, `tests/UiState/RegexPartialChecks.cs`, `tests/UiState/RegexFinishChecks.cs`, `tests/UiState/RegexFinishMoreChecks.cs` and `tests/UiState/RegexFinishLocalizationChecks.cs` `tests/UiState/RegexGrepAttributeEncodingChecks.cs` and `tests/UiState/RegexRestLocalizationChecks.cs` and `tests/UiState/RegexGrepToolChecks.cs`). The checks added with the last wave (tree editing, templates, layout, preferences, keyboard map, folder-search extras, result lists, action files and command line, filter queries, engine versions and the Cantonese coverage) were each watched failing once by deliberately breaking the code they protect. The checks do not prove layout, focus order, keyboard use inside the popover, dialogs (including the new file open and save dialogs), the folder browser, the new tabs and sections, or pixels. The Perl and Ruby output and the PowerShell script were also run once by hand against the real tools (Perl 5, Ruby 3.3, PowerShell 7) on one pattern with each kind of code; that run is not repeated by the checks. The folder search and its undo were exercised on temporary folders by the checks, not on a real project.

## Engine binding

- Engine: `System.Text.RegularExpressions` on .NET 10, regular expression dialect ".NET". The builder never silently substitutes another engine.
- The non-backtracking engine is used whenever the pattern allows it. Patterns that need backtracking (lookarounds, backreferences, atomic groups, conditionals, balancing groups, `RightToLeft`) run on the backtracking engine with a 250 ms limit per match.
- Flags offered (8): IgnoreCase, Multiline, Singleline, IgnorePatternWhitespace, ExplicitCapture, CultureInvariant, RightToLeft, NonBacktracking. RightToLeft uses the backtracking engine. NonBacktracking means "require the linear-time engine": a pattern that needs backtracking is reported as unsupported instead of falling back, and combining it with RightToLeft is refused.
- Limits: 4096 pattern characters, 64 KiB sample, 2000 highlighted matches, 2 s per test, 256 KiB replace output, 2000 split pieces, 200 test cases, 200 saved patterns, 50 remembered experiments (1 MiB, 16 KiB sample each). Folder search: 2 MiB per file by default (16 MiB ceiling), 5000 files (20000 ceiling), 1000 results (5000 ceiling), 200 matches per file, 128 MiB read in total, 15 s; replacement plans cover at most 500 files and 256 MiB, and 10 undo snapshots are kept. Scope testing: 5000 scopes and 2000 matches per run, 2 s. Hex view: 4 KiB. Loading a file: the first 64 KiB. Pattern comparison: 8 patterns, 4 s.

## How the flavor table was verified

Each construct in `RegexBuilderFlavors.cs` has a small probe pattern and a text it must match. During development every probe was run with the real engines: PHP (PCRE2), Node, Python 3.14, Go, ripgrep and GNU grep 3.0 (`-E`), and the table was corrected until the match and no-match results agreed with every cell. Two JavaScript cells (the `s` and `m` options) can only be written as flags, so they were checked separately. The probe for right-to-left matching is empty because the other engines have no equivalent. Only the .NET column is re-checked automatically (`RegexRemainingChecks`), including a deliberately corrupted cell that must be caught. Same-meaning notes such as "ASCII only" and the version remarks come from documentation, not from the probes.
