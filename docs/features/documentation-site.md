# Documentation site, downloads and offline package

The documentation site is generated by `website/render.mjs` from `website/template.html`, the Markdown in `docs/` and `wiki/`, the project overview files and the feature inventory. It is deployed by `.github/workflows/pages.yml`. This article describes the delivery parts of that site and how each one fails.

## Latest release download panel

The home page has a **Download the latest release** panel. Its script asks `https://api.github.com/repos/Ding-Ding-Projects/material-docker-image/releases/latest` when the page is viewed, so nothing about a version is written into the page.

- **Ready.** The panel shows the version (the release tag), the UTC publication time, a **Setup.exe** button, a **Build companion** button for `MaterialDockerImageBuild.exe`, an **Offline documentation** button for `MaterialDockerImageDocs.zip`, and a list of every attached file with its size. If one of the three named files is not attached to that release, its button says so instead of linking anywhere.
- **Loading, offline, rate limited, no latest release, unreadable reply.** Each state has its own plain message in English, Cantonese or both, and the **Open the releases page** link stays available. No state ever shows a version.
- **Link safety.** Only assets whose download address is under this repository's `releases/download/` path are shown, and a malformed reply is rejected as a whole.
- **Latest means main.** The release workflow marks only releases built from the current `main` tip as the latest release, so branch builds never appear in this panel.
- The unsigned installer warning is repeated next to the buttons.

## Link previews

The page head carries Open Graph and Twitter card metadata that point at `social-preview.png`, a 1200 x 630 image. It is composed by `scripts/make-social-preview.mjs` from a real capture of the built application (`evidence/screenshots/build.png`); the script scales the capture to the card width and adds a flat accent band, and it draws nothing that is not in the capture. The committed PNG is listed with its hash in `website/content-manifest.json`. Previews are fetched by the platform that displays a shared link, so a cached older preview can remain visible after an update.

## Front provenance

The home page states the documentation source version and an update time. Both come from `website/provenance.json`: the version is the application project version, and the time is the committer date of the latest commit that touched any rendered source (`node website/render.mjs --stamp` reads it). The stamp is stored, not computed during a render, so rendering stays deterministic and `--check` stays meaningful. This is the version of the documentation sources, not the running application's release; the release version appears in the download panel after it loads. A stamp is refreshed in a follow-up commit after the source commit it describes.

## Search across all documentation

The search field above the articles searches every embedded article and wiki page. Matching sections are listed, each linking to the heading it came from, with a snippet.

- **Plain text first.** The field matches the text exactly as typed; punctuation has no special meaning. **Ignore case** is on by default.
- **Regex builder (Alt+R).** The adjacent panel switches to JavaScript regular-expression syntax, has i, m, s and u flag toggles, a pattern field kept in sync with the search field, buttons that insert common tokens at the cursor (classes, anchors, groups, lookaround, repetition), and a small pattern library. An invalid pattern shows the engine's message and marks both fields invalid.
- **Bounds.** Patterns are limited to 200 characters. A group that repeats while already containing a repeat (the usual runaway shape) is refused before it runs. Each section is searched in its first 20,000 characters, at most 200 results are shown, and a search stops after 250 ms; each cut-off is reported in the status line. These bounds exist because a running browser regular expression cannot be interrupted.
- **Languages.** Labels and messages follow the page language selector (English, Cantonese, or both).
- **Not RegexBuddy parity.** This is a bounded builder for finding documents. It has no match explanation tree, replace preview or sample tester, and the panel says so.

## Offline documentation package

`build/package-docs.ps1` (run by `build-installer.bat` and by the release workflow) writes `out/docs/MaterialDockerImageDocs.zip` and `out/receipts/docs.json`, and copies both into `out/releases` so they are attached to the release.

- The archive holds `index.html`, `content-manifest.json`, `feature-inventory.json`, `favicon.svg` and the embedded evidence images under `assets/`. It is the same complete corpus as the hosted site. Extract it and open `index.html`; it needs no network.
- It is produced by `node website/render.mjs --offline out/docs/site`, which removes link-preview metadata and disables the release lookup (the panel explains that this is the offline package and links to the releases page). The script refuses to write outside `out/docs`.
- Before archiving, the script fails if the page references a remote asset (`src`, `link href`, `url()` or `@import` to http or https). Entries use a fixed order and timestamp so one source produces one archive.
- The receipt binds the archive hash to the exact source commit and build inputs. The release workflow checks that receipt's source and that both files are attached.
- Links to GitHub source pages inside articles are ordinary links, not assets, and need a network when followed.

## Failure modes

- A stale `website/index.html` or manifest fails `node website/render.mjs --check` and the checklist checks; run `node website/render.mjs` and commit the result.
- A missing, malformed or untimestamped `website/provenance.json` stops rendering with an instruction to stamp.
- A missing `website/social-preview.png` stops rendering; regenerate it with `node scripts/make-social-preview.mjs`.

## Verification

`node scripts/test-feature-checklist.mjs` covers the release parsing and every failure state, the preview metadata and image dimensions, provenance consistency, the search core and its bounds, anchors and heading ids, the offline package contents and links, and the workflow asset readback. It does not cover pixels or a deployed page. Interactive behaviour was exercised once in headless Microsoft Edge against the generated page (live release lookup, plain and regex search, validation messages, Cantonese messages); the deployed site and the first release carrying the documentation archive remain to be verified.
