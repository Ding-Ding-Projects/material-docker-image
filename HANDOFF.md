# Implementation handoff

## Objective

A native Windows WPF workspace for Docker with a complete Material 3 interface. The November 2026 rewrite replaced every window surface, added the Dockerfile Creator, live monitoring, cleanup, registry, diagnostics, tools, settings and local history destinations, and replaced every screenshot with captures of the built application.

## Structure

- `src/MaterialDockerImage/Themes/Material.xaml`: Material 3 roles and control templates (buttons, fields, combo boxes, switches, chips, segmented buttons, rail and tab items, lists, menus, tooltips, scroll bars, sliders, expanders).
- `Shell/`: overlay host (in-window dialogs, super confirmation), operation panel, command palette.
- `Services/`: `AppHost` (engine access, foreground operations with real results, background reads, navigation and hand-offs), theme, language and funny levels with the personal wording overlay, notifications, command registry, narration, local history (LibGit2Sharp).
- `UI/`: shared builders (`Ui`), `DataTable<T>` (search with regex builder, filters, multi-select, bulk bar, context menus with shortcuts, export), `SearchFilter`, structured input validation, Dockerfile graph, the Creator model, parser, starters, lint and undo history, the Base64 toolkit, icons generated from the Material Symbols codepoints.
- `Pages/`: one class per destination with helpers in a folder per destination.
- `Assets/Fonts/`: Material Symbols Rounded subset to the icons in use (outline and filled, Apache 2.0).
- `design/workspace-redesign-2026-11/`: the design canvas for every screen, with its handoff and review notes.

## App identity

- `UI/AppIdentity.cs` holds the framework-free display-name, symbol and custom-logo rules; `Shell/AppLogo.cs` decodes and shows the logo; `Pages/Settings/LogoPicker.cs` is the Appearance row. The multi-size icon lives in `Assets/Icon/` and is regenerated by `build/make-icon.py`. Interactive verification in the built window is pending.

## Records, exports, shortcuts, info icons and updates

- `build/make-changelog.ps1` writes `src/MaterialDockerImage/Assets/changelog.json` from git log (deterministic, merge commits omitted, grouped under the first containing `vX.Y.Z` tag, the rest as unreleased). `build/publish.ps1` runs it before every build; the file is git-ignored and embedded when present. `UI/ChangelogModel.cs` parses and filters it; `Pages/Tools/ChangelogView.cs` is the viewer (regex search, typed dates, copy and Markdown export, commit links behind a confirmation).
- `UI/TableExport.cs` serialises every `DataTable` export and copy-as (CSV, TSV, JSON schema 1, Markdown, HTML).
- `Ui.CommandMenuItem` derives shortcut text from `AppCommand.Gesture`; `tests/UiState/RecordsChecks.cs` scans the source and fails on a hand-typed shortcut that is not a declared list-local key.
- `Ui.Info` is the one info-icon component; `SettingRows` falls back to `UI/InfoGuidance.cs` text for rows without hand-written guidance.
- `UI/UpdateFeed.cs` (version comparison, RELEASES parsing, decision) is framework-free and checked; `Services/UpdateService.cs` fetches the feed and runs Update.exe only for an installed copy; `Shell/UpdateBanner.cs` shows the unsigned-build banner and restarts only after confirmation. Nothing here has been run against a published feed or an installed copy.
- Verification: `build.bat -Tests` passes (UI-state checks including the new ones, each logic piece seen failing first by sabotage); `build.bat -Version 0.0.1` compiles. Nothing was driven in the built window and no capture was taken.

## Known limits

- Language modes cover the shell and the copy of every destination page (about 3,200 Cantonese phrases and sentence templates). Docker CLI output, engine data, log lines and some long explanations assembled from several fragments are shown as produced and stay English in every mode.
- Density has little visible effect and the external editor setting is used by Build only. Momentum shows a session streak chip.
- Settings safety (docs/features/settings-safety.md): settings rows and major page buttons can be locked with confirm-only, PIN or authenticator-app policies (credentials in `locks.json`, not settings.json), unlocked through the ladder (confirm, credential, persistent exponential wait, single-use recovery codes), and Tools has an Authenticator section with an in-process QR code. Seven settings (language, theme, density, accent colour, font size, motion, display name) can be scheduled by time, weekday and optional date range, with a local JSON file, an https address or a Home Assistant entity as value source. Action sounds have a volume and quiet hours. Filter bars and statistic strips collapse and persist.
- Built and driven in the window (receipt, 38 steps): PIN, password, authenticator and combined lock policies with unlock durations and a timed relock, locks on any control, tab, tab-group and appearance-value locks, the Locks manager, the PIN keypad, the dish, sums and whack-a-mole ladder rungs, Support Tickets, School mode with a PIN, the per-element appearance editor, the general authenticator with QR import from an image. Built with logic checks only: the School mode Windows Hello choice, pointer clicks on locked controls and clipboard QR import (all need the visible desktop or the host clipboard). Not built: camera QR capture. The https and Home Assistant schedule sources have never talked to a real server; DPAPI token storage and reduced-volume playback have not been tried on a real profile and audio device.
- Regex builder (docs/features/regex-parity.md: 75 of 83 topics implemented, none partial, 8 unavailable because .NET cannot do them): plain-language blocks, rare .NET constructs, split preview, expected-outcome test cases, backtracking diagnostics, conversions (C#, PowerShell, JSON, grep -E and -P, ripgrep, Select-String, JavaScript, Python, Java, Go, PHP, Perl, Ruby, PowerShell script), library import/export, eight flags, folder search with dry-run replacement, confirmed apply and undo snapshots (`RegexBuilderGrep.cs`), match navigation, replacement explanation, tree export, parameters, a seven-engine flavor table, remembered experiments, POSIX class conversion, a Unicode block picker, style tips, per-token help, line and page scopes, a hex view, file load and save, pattern comparison and saved pattern descriptions. The last wave adds editing through the explanation tree (`RegexBuilderTreeEdit.cs`), editable code templates (`RegexBuilderTemplates.cs`, `regex-templates.json`), a panel layout, preferences and keyboard map (`RegexBuilderPreferences.cs`, `regex-preferences.json`, loaded in `App.xaml.cs`), folder-search date windows, context lines, saved result lists and open-in-editor (`RegexBuilderGrepResults.cs`), action files and the `--regex-pattern` / `--regex-action` start-up arguments (`RegexBuilderActions.cs`, `CommandPalette.Open`), builder buttons on the library, my-patterns and Unicode block filters (`SearchFilter` reuse, `SearchBuilderPopover.Finish.cs` keeps the second popup open while a nested builder is open), engine version pickers (`RegexBuilderFlavorVersions.cs`) and Cantonese for help pages, tips, verdicts and reports (`LocStrings.RegexFinish.cs`, `RegexBuilderText.cs`). Logic checks: `tests/UiState/RegexFinish*Checks.cs`, each watched failing under a deliberate break. None of the new sections or dialogs was driven in a window, the stacked nested popup in particular. The popover was opened from the Containers search in the built 0.99.25 window on a hidden desktop and rendered its flags, tabs and tools; the individual tool sections were not driven. Full RegexBuddy parity remains open; the eight unavailable topics (debugger trace, step counts, possessive quantifiers, recursion, class intersection, branch reset, replacement conditionals) are impossible on the .NET engine.
- Health checks, device mappings and GPU access are complete in the run editor and the Containers inspector, with focused checks and a real-engine argument receipt (evidence/container-controls-2026-11.json); they were not driven in the built application and no physical GPU was tried. Interactive terminals open in a separate console window; the classic console option (Settings › Engine) was exercised end to end on a hidden desktop.
- Layout matrix: `--capture-probe` checked 264 surfaces (three languages at 1440, 1200 and 960 px, light theme, 200 % scale) and the clipping it found was fixed; the final run (main 5c048f4) reports no cut and no overflow, after the probe was changed to ask WPF for each text width at the real DPI and tab strips stopped squeezing labels (evidence/layout-matrix-2026-11/summary.json). The CI screenshot run does not use the probe yet.
